## 现在做：东鹏换用户

H5 / 接口不直接调微信。只调东鹏，换成我们用户。

我们侧固定三个动作：

1. 用 URL 上的 ticket（或他们给的参数）调东鹏换用户
2. 我们库按 openid（或他们给的唯一 ID）建/更新用户，签发我们自己的 token
3. 之后答题、抽奖、填地址全部带我们的 token

东鹏文档未到时：适配层先走 mock（固定返回一个测试用户）。他们接口到了，只改适配层，问答和抽奖不用动。

调通时必须向东鹏要到：接口地址、鉴权、测试环境、一份成功返回示例。

## 现在做：抽奖逻辑（按附件一，服务端裁决）

| 规则 | 实现 |
|------|------|
| 未授权 | 不能玩 |
| 已参与 | 直接结果页，不能再抽（次数 X 若 >1，按剩余次数） |
| 未答完 5 题 | 不能抽 |
| 答对 < 3 | 不能抽，回首页 |
| 答对 ≥ 3 | 可以抽一次（若 X>1，按配置） |
| 点「开始抽奖」 | 服务端先开奖再让前端播动画，结果以服务端为准 |
| 库存为 0 | 该奖不再中，落到未中奖或下一档 |
| 实物中奖 | 填姓名、电话、地址后才算领取 |

开奖过程：校验资格 → 按后台概率抽 → 扣库存（Redis 防超卖）→ 写抽奖记录。  
幂等：同一用户同一场重复点「开始抽奖」，返回已有结果，不连抽。

次数 X、奖品、概率后台可配，先给默认：X=1；谢谢参与 + 1～2 个实物占位。

## 现在做：抽奖后台

先做能配活动、能看名单的最小后台，不套东鹏视觉。

- 登录（先独立账号）
- 活动：次数 X、满几题可抽（默认 3）、是否上线
- 题库：增删改、选项、正确答案
- 奖品：名称、图、类型（实物/谢谢参与）、概率、库存
- 名单：答题记录、抽奖结果、领奖地址，可导出
- 操作日志
