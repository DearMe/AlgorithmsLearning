# 东鹏已确认：用公众号 openid 进我们系统

对方 8 月 17 日回复已锁定换用户方式和部署形态。

## 换用户（按他们的做法）

进页走 **东鹏饮料公众号授权**，前端处理。拿到的是 **公众号 openid**（`wxOpenid`），不是小程序 openid。

```
小程序 web-view 打开：
https://wx-bak.xdp8.cn/get/openid/from/gzh?callbackUrl=我们H5完整地址

他们授权完后跳回我们页面，URL 带：
?wxOpenid=oXXXX

我们 H5 把 wxOpenid 交给我们服务端
  → 按 wxOpenid 建/更新用户
  → 签发我们自己的 token
  → 之后问答、抽奖、填地址只用我们的 token
```

他们明确：若要东鹏侧会员资料，必须小程序 `wx.login` + code，H5 做不到。本活动第一期 **只用 wxOpenid 当用户载体**，会员信息、发券等暂不调他们接口。领奖姓名/电话/地址在我们表单采集。

## 我们必须自己做的鉴权（不要信任 URL 一直带着 openid）

`wxOpenid` 出现在 query 里，可被改。抽奖不能每次请求都信前端传来的 openid。

正确做法：

1. 进入页面读到 `wxOpenid` 后，立刻 `POST` 给我们后端，换我们 token（存 cookie / header）
2. 清掉地址栏里的 `wxOpenid`（replaceState），避免分享把别人的 openid 带出去
3. 答题、抽奖接口只认我们 token
4. 没有 token、没有 wxOpenid：跳回  
   `https://wx-bak.xdp8.cn/get/openid/from/gzh?callbackUrl=当前页`

仍要问他们：`wxOpenid` 有没有签名或时效。没有的话只能防君子，抽奖风控靠次数和设备侧补充。

## 小程序 web-view 入口

web-view 的 `src` 应是他们的授权地址，`callbackUrl` 指向我们活动页（需 URL 编码）。  
`wx-bak.xdp8.cn` 和我们活动域名都要加进小程序 **业务域名**。

## 部署（按他们的做法）

到时给一台新机器，域名他们提前解析。我们仍要确认：系统、PHP/MySQL/Redis/Nginx、SSH、证书、校验文件、业务域名。

## 第一期不调他们的用户信息接口

附件一只需要：用微信身份判断是否已参与、答题、抽奖、填地址。用 `wxOpenid` 落我们库即可。结果页跳会员中心只要他们给链接。
