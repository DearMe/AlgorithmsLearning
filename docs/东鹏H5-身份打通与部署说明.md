# 用户身份怎么拿到，以及怎么部署到东鹏服务器

结论先说：

1. **openid 只能由东鹏小程序 + 东鹏服务端向微信换，不能由我们的 H5 自己调微信。**
2. **换到人之后，用一次性 ticket 打开我们的 H5，之后问答/海报/抽奖全部走我们 ThinkPHP。**
3. **部署到他们服务器，本质是：公网 HTTPS 域名 + Nginx + PHP + MySQL + Redis；web-view 必须能从公网打开这个域名。**

下面分三块：能拿到什么、推荐链路、部署方式。末尾是发给东鹏的接口草案和要他们拍板的题。

---

## 1. 在小程序 web-view 里，谁能拿到 openid

| 方式 | 能不能拿到 openid | 说明 |
|------|-------------------|------|
| H5 里调 `wx.login` | 否 | `wx.login` 只存在于小程序原生页 |
| H5 里走公众号网页授权 `snsapi_base` | 基本不可用 | web-view 不是普通微信内置浏览器，授权页经常失败或被拦 |
| H5 直接调微信 `jscode2session` | 否 | 必须 AppSecret，且只能服务端调；Secret 在东鹏手里 |
| 小程序原生页 `wx.login` → 东鹏服务端换 session | **是，标准做法** | 唯一稳定来源 |
| 东鹏已有会员 token / SSO | 是（拿到的是会员 ID，openid 看他们接口是否带回） | 若他们已登录会员，可少做一步微信登录 |
| 我们向东鹏要小程序 AppSecret 自己换 | 理论上能，实际上不要作为方案 | 对方基本不会给；泄露风险在他们 |

微信官方接口（**只允许东鹏服务端调**，我们不碰 AppSecret）：

```
GET https://api.weixin.qq.com/sns/jscode2session
  ?appid=小程序AppID
  &secret=小程序AppSecret
  &js_code=wx.login拿到的code
  &grant_type=authorization_code
```

返回大致为：

```json
{
  "openid": "用户在该小程序下的唯一ID",
  "session_key": "会话密钥，不能传给前端",
  "unionid": "仅当小程序已绑微信开放平台时才有"
}
```

补充能力（都在小程序侧，H5 做不了）：

| 信息 | 怎么拿 | 我们怎么用 |
|------|--------|------------|
| openid | `wx.login` + `jscode2session` | 活动用户主键（或和会员 ID 二选一） |
| unionid | 同上，前提是绑开放平台 | 和公众号、其他小程序是不是同一个人 |
| 手机号 | 小程序按钮 `open-type="getPhoneNumber"`，东鹏服务端再调 `getuserphonenumber` | 领奖、发货、短信 |
| 昵称头像 | 微信已收紧，不要依赖旧接口 | 海报上需要再单独做填写/授权 |
| 东鹏会员 ID、积分、等级 | 东鹏会员中台，用他们的 token 查 | 是否必须会员才能玩、发积分/券 |

**不要做：** 把 openid 明文拼在 web-view URL 上。可伪造，抽奖必被刷。

## 2. 推荐链路：东鹏只负责「认出人」，之后全走我们系统

```
用户点活动
    │
    ▼
东鹏小程序页面
    │  1. wx.login() 得到 code
    │  2. code 发给东鹏服务端
    │  3. 东鹏调微信 jscode2session → openid / unionid
    │  4. （可选）绑定会员、取手机号
    │  5. 签发一次性 ticket（30～120 秒，用一次就作废）
    ▼
打开 web-view
    https://活动域名/qa?ticket=xxx&activity=xxx&channel=xxx
    │
    ▼
我们 Vue3 H5
    │  把 ticket 交给我们 ThinkPHP（不要长期放 URL）
    ▼
我们后端 POST 东鹏「ticket 换用户」
    │  拿到 openid / unionid / memberId / 手机号（他们给什么用什么）
    │  在我们库 upsert 用户，签发我们自己的 token（JWT 或 session）
    ▼
之后全部我们的接口
    答题 / 判分 / 海报 / 抽奖 / 后台
    需要发券、加积分时，再用 openid 或 memberId 调东鹏履约接口
```

H5 侧登录态建议：`Authorization: Bearer <我们的token>`，放内存或 `localStorage`。不要依赖第三方 cookie，web-view 里 iOS 很容易丢。

若东鹏已经有「小程序登录后的会员 token」，可以不单独做 ticket：把他们的 token 当 ticket 用，我们后端拿这个 token 调他们的「当前用户」接口即可。本质一样。

### 2.1 请东鹏提供的接口（最小集）

**接口 1：用 ticket（或他们的登录 token）换用户 — 必须有**

- 方向：我们服务端 → 东鹏服务端  
- 鉴权：IP 白名单 + 签名，或他们发 AKSK  
- 建议返回：

```json
{
  "code": 0,
  "data": {
    "openid": "oXXXX",
    "unionid": "oYYYY 或空",
    "memberId": "他们会员ID，没有就空",
    "mobile": "有就给，没有就空",
    "nickname": "可选"
  }
}
```

**接口 2：发券 / 加积分 — 有这类奖才要**

中奖后我们传：`openid` 或 `memberId` + 奖品编码 + 幂等单号。

**接口 3：手机号 — 领实物才要**

若 ticket 里已经带手机号，可省略。否则要小程序先授权再写入 ticket。

### 2.2 两种可落地的变体（让东鹏选一个）

**方案 A（推荐）：ticket**  
小程序不把 code 给我们。东鹏换好 openid，签发 ticket。我们只认 ticket。  
对方改动：小程序 web-view 拼 URL；服务端一个短时 ticket 接口。

**方案 B：把 code 给我们，我们调东鹏「code 换用户」**  
东鹏仍自己调微信，不把 Secret 给我们。  
风险：code 只有几分钟、只能用一次，拼在 URL 上容易被日志记下来，不如 ticket。

**不要选：给我们 AppSecret。**

### 2.3 我们系统里怎么落用户

我们库自己建用户表，例如：

- `id`：我们自己的用户 ID（答题、抽奖都用这个）
- `mp_openid`：该小程序 openid
- `unionid`
- `member_id`
- `mobile`

唯一键：优先 `mp_openid`，有会员体系再加 `member_id`。  
抽奖资格、次数、黑名单都以我们这张表为准，不每次问微信。

## 3. 部署到东鹏服务器

web-view 有硬条件：**H5 必须是公网可访问的 HTTPS，且域名在小程序「业务域名」白名单里。**  
机器可以在东鹏内网，但前面必须有公网 Nginx/WAF 反代出来。纯内网 IP 用户打不开。

### 3.1 推荐部署形态

```
公网 HTTPS（东鹏已备案域名，例如 h5-act.dongpeng.com）
        │
        ▼
东鹏 Nginx / WAF
        │  /        → Vue3 打包后的静态文件
        │  /api     → php-fpm（ThinkPHP）
        │  /xxxxx.txt → 小程序业务域名校验文件（根目录）
        ▼
一台 Linux（或容器）
        ├── PHP 8.0+（按现有 ThinkPHP 版本）
        ├── MySQL（活动库：用户、题库、抽奖、中奖）
        └── Redis（库存、限流、我们自己的 token）
```

后台管理（抽奖配置）建议：

- 同一套 ThinkPHP，路径 `/admin` 或独立子域
- 仅东鹏办公网 / VPN 可访问，或加 IP 白名单  
- 不要和 H5 一样对全世界敞开

### 3.2 三种落地，让东鹏选

| 方案 | 做法 | 优点 | 缺点 |
|------|------|------|------|
| **1. 独立机 / 独立容器（推荐）** | 他们给 1 台 Linux 或 1 个 Docker 主机，我们按现有 LNMP 部署 | 和现有项目一致，出问题好查 | 他们要开端口、证书、出网白名单 |
| **2. 进他们现有 PHP 集群** | 代码放到他们规定目录，接入他们的 Nginx/PHP | 运维统一 | PHP 版本、扩展、禁止函数、Redis 未必匹配，联调慢 |
| **3. 静态在他们 CDN，API 在我们云** | 只把 Vue dist 放到他们域名，接口仍打我们服务器 | 部署少 | 跨域、他们安全可能不允许；openid 链路仍要他们配合 |

私单、要抽奖库存，优先 **方案 1**。抽奖扣库存、防刷都在我们 Redis/MySQL，不跟他们业务库绑死。

### 3.3 上他们机器时我们要准备的包

1. Vue3：`npm run build` 产出 `dist/`  
2. ThinkPHP：代码 + `composer install --no-dev`  
3. `.env`：数据库、Redis、东鹏 ticket 接口地址和密钥（密钥不要进 Git）  
4. SQL：用户/活动/题库/奖品/中奖表  
5. Nginx 示例：HTTPS、静态、反代 `/api`、校验文件、禁止访问 `.env`  
6. PHP 扩展：`pdo_mysql`、`redis`、`curl`、`mbstring`、`openssl`、`gd` 或 `imagick`（海报若服务端出图）  
7. 进程：`php-fpm`；队列若有抽奖异步再加 supervisor  
8. 业务域名校验文件放到站点根目录

发布建议：测试环境先通 web-view，再镜像到生产。我们给发布脚本（rsync / git pull + 清 opcache），他们堡垒机执行。不要在生产手工改 PHP。

### 3.4 网络要他们开的洞

| 方向 | 用途 |
|------|------|
| 用户手机 → 公网 443 | 打开 H5 |
| 我们 PHP → 东鹏会员/ticket/发券 API | 换用户、发奖 |
| 我们 PHP → `api.weixin.qq.com` | 一般不需要；微信登录由东鹏调。只有他们坚持把 Secret 给我们才需要 |
| 我们 PHP → 对象存储（若海报图上 OSS） | 保存海报 URL 给小程序 downloadFile |
| 运维 → SSH/堡垒机 | 发布 |
| 东鹏办公网 → 后台域名 | 配奖品、导出中奖 |

### 3.5 和「业务域名」的关系

部署在谁的服务器，域名就要能指过去：

- 域名用东鹏的（例如 `act.xxx.com`）→ DNS 指到这台机，证书他们出，校验文件我们放根目录，他们在小程序后台配业务域名  
- 域名用我们的 → 机器其实不必在东鹏机房；他们仍要在小程序后台配置我们的域名  

**若合同要求代码必须在东鹏机房，用东鹏域名指到他们给的那台机。**  
身份链路不变：openid 仍然东鹏换，我们只在他们机上跑 PHP。

## 4. 请东鹏技术直接回答（本页范围）

**身份**

1. 选方案 A（ticket）还是方案 B（code 给我们，你们换用户）？  
2. 「ticket/token 换用户」接口文档、测试环境、鉴权方式、IP 白名单申请？  
3. 返回字段有哪些：openid、unionid、memberId、mobile？  
4. 小程序是否已绑开放平台（有没有 unionid）？  
5. 未注册会员能否先用 openid 玩，领奖再绑？  
6. 手机号是否必填？若是，小程序页能否先授权再开 web-view？

**部署**

7. 能否提供独立 Linux（或 Docker）？OS、能否装 Docker、有无 root？  
8. PHP / MySQL / Redis 版本，还是我们必须用他们集群指定版本？  
9. 公网域名、证书、备案主体？谁配 Nginx 和业务域名校验文件？  
10. 这台机出网能否访问你们会员 API、对象存储？  
11. 发布方式：堡垒机 + git、Jenkins、还是我们只交安装包？  
12. 抽奖后台是否必须 VPN？  

这 12 条对齐后，就可以按现有 ThinkPHP + Vue3 项目迁上去，不必改身份模型。
